介面實例集

十則現成的配方，複製指令就能用。 每一則的會改幾行、那個元素實際顯示什麼字，都是先查過才寫上來的。 全部用同一支萬用工具。

🛟 動手之前：先完整備份整個遊戲資料夾

把整個遊戲資料夾複製一份到別的地方， 包括裡面存放紀錄的資料夾。不要挑檔案，整包複製最省事也最保險。

「紀錄」是指這些（它們跟遊戲檔混在同一個資料夾裡）：

  • Support\MVP Baseball 2005\ —— 遊戲自己建的， 裡面是設定（MVPOptions_Options.sav）與手把設定 （controller.cfg）。剛安裝好時沒有這個資料夾，玩過才出現。
  • 王朝、老闆模式、名單與玩家檔案的存檔（*_Franchise.sav、 *_Owner Mode.sav、*_Rosters.sav、*_Profile.sav）—— 沒有固定的資料夾名，你或你裝的模組包叫它什麼它就叫什麼。找不到就用這一行找：
dir /s /b "〔你的遊戲資料夾〕\*.sav"
find "〔你的遊戲資料夾〕" -name "*.sav"

上面第一行 Windows、第二行 Mac。 本站每一支工具都會自己備份它要動的那一個檔， 但那只保得住那一個檔 —— 整包備份保的是「你玩到現在的一切」。 完整做法看備份與還原 SOP。

⚡ 只想趕快改掉一則？照這四步

  1. 先照萬用工具那一課把 mvp_fel_toolkit.py 準備好，並確認自己的遊戲資料夾在哪。
  2. 挑一則配方，把指令裡的 你的遊戲資料夾 換成你自己的路徑，先不加 --apply 跑一次看預覽（這裡以 A3 球速數字為例）
    python mvp_fel_toolkit.py "你的遊戲資料夾" --toggle fes_ingameoverlay.fel PITCHSPEED1 off
  3. 預覽列出來的就是你想改的元素，同一行加 --apply 真的改，要看到「✅ 複驗通過」與「目標元素 0 個未套用」
    python mvp_fel_toolkit.py "你的遊戲資料夾" --toggle fes_ingameoverlay.fel PITCHSPEED1 off --apply
  4. 不論改了幾則、改了幾次，這一行都回到你第一次動手之前
    python mvp_fel_toolkit.py "你的遊戲資料夾" --restore

A1、A2 這種左右 HUD 各一行的，fes_hudleft.fel 與 fes_hudright.fel 要各下一次。 想知道每一則在改什麼，往下讀；只想複習，跳到📌 重點整理。

前置：先把工具準備好

  • 下載萬用工具並照那一課做過一次
  • 知道自己的遊戲資料夾在哪

下面所有指令裡的 你的遊戲資料夾 都要換成你自己的路徑。 先不加 --apply 跑一次看預覽，確定行數對得上再真的改。

三件事先講

一、行數是本站在測試機的檔案上量的，不是 EA 原版。你手上那份若裝過其他模組，數字可能不同。 只要預覽列出來的是你想改的東西，就可以繼續。

二、本站沒有實機跑過每一則的畫面結果。 能保證的是「檔案確實被正確修改、可以完整還原」， 不能保證「遊戲一定會照你想的顯示」。

三、隨時可以全部還原：--restore 一行，位元組完全一致。

A 組：關掉比賽畫面上的東西

A1 · 打者之眼

畫面上那個 Hitter's Eye 標籤。左置與右置 HUD 各一行，兩邊都要改。

python mvp_fel_toolkit.py "你的遊戲資料夾" --toggle fes_hudleft.fel HITTERSEYE off --apply
python mvp_fel_toolkit.py "你的遊戲資料夾" --toggle fes_hudright.fel HITTERSEYE off --apply
預覽會說

每個檔找到 1 行 · 會改動 1 行。

A2 · 打者姓名

HUD 上顯示打者名字的那一格。同樣左右各一行。

python mvp_fel_toolkit.py "你的遊戲資料夾" --toggle fes_hudleft.fel BATTERNAME off --apply
python mvp_fel_toolkit.py "你的遊戲資料夾" --toggle fes_hudright.fel BATTERNAME off --apply

用 --strings 查這個元素，會看到它的預設文字是一個球員名字 —— 那是 EA 拿來當版面範例用的。

A3 · 球速數字

投完球之後跳出來的那個速度數字。1 行。

python mvp_fel_toolkit.py "你的遊戲資料夾" --toggle fes_ingameoverlay.fel PITCHSPEED1 off --apply

怎麼確定是這一個

先查它的文字：

python mvp_fel_toolkit.py "你的遊戲資料夾" --strings fes_ingameoverlay.fel

會看到 PITCHSPEED1 的文字是 999 —— 三位數的佔位字串，正好對得上球速。

A4 · 出局／安打之類的結果字樣

fes_ingameoverlay.fel 裡的 MESSAGE，3 行， 文字是 Out。

python mvp_fel_toolkit.py "你的遊戲資料夾" --toggle fes_ingameoverlay.fel MESSAGE off --apply
提醒

同一個封裝檔裡的 fes_ingamechat.fel 也有一個 MESSAGE，那是聊天訊息， 跟這個無關。指令有指定檔名，所以不會改到它。

A5 · 跑壘者速度數值

壘包鑽石圖上每個壘包旁邊那個兩位數，都在同一個檔。本站測試機那一份是 6 行，你手上那份可能不同。

python mvp_fel_toolkit.py "你的遊戲資料夾" --toggle fes_ingameinfobar.fel RATING off --apply

這一則有專屬教學， 裡面解釋了為什麼本站測試機那一份是 6 行而不是 4 行。

B 組：把這台機器上關掉的東西打開

B 組要先說清楚

下面這些元素在本站測試機的檔案裡開關是 0。本站把它們的文字查出來了， 所以知道它們原本要顯示什麼。

⚠️ 2026-08-25 訂正：這一組原本叫「把 EA 自己關掉的東西打開」，方向講反了。拿剛安裝好的原版一比就知道 —— 見下面 B1。

但本站沒有驗證遊戲是否真的會用到它們。 FEL 速查記載過：群組的開關會被遊戲程式在執行時覆寫。 所以把開關打開，很可能什麼都不會發生。

這一組的價值是「看看檔案裡有什麼」，不是「解鎖隱藏功能」。 未驗證

B1 · 揮棒時機回饋

fes_ingameoverlay.fel 裡有六個關掉的貼圖元素， 分成左右兩組，各是 EARLY / LATE / PERFECT。 這六個名字在本站測試機這一份裡各出現 5 行（同一個名字散在好幾個畫面）， 所以預覽會說「找到 5 行」：

python mvp_fel_toolkit.py "你的遊戲資料夾" --toggle fes_ingameoverlay.fel PERFECTR on

另外五個是 EARLYR、LATER、PERFECTL、EARLYL、LATEL。 它們的父群組 FEEDBACKR 與 FEEDBACKL 本身是開著的， 只有裡面這六個圖是關的。

這一項不是「EA 關掉的」，是這台機器上被關掉的

同一個檔在剛安裝好的原版裡也存在，兩份都是 290 行。 把裡面所有 EARLY / LATE / PERFECT 的行撈出來比：

總行數開著關著
剛安裝好的原版362412
本站測試機36036

原版有 24 行是開著的。所以打開這些開關， 不是「解鎖 EA 藏起來的東西」，是還原模組關掉的東西 —— 這台機器上跑的名冊模組把它們全關了。

為什麼模組要關掉揮棒時機回饋，本站不知道 （最省事的猜測是「玩起來比較難」，但那是猜的，沒有證據）。 未解

B2 · 兩組帶文字的介面

元素查出來的文字裡面有什麼
GR:ARGUMENTMETERArgument Intensity 黑底 + 進度條 + 文字 + 按鈕圖示
GR:CHARGEMOUNDTo Charge Mound Press 黑底 + 文字 + 按鈕圖示
SH:NEXTFIELDER（沒有文字）一張貼圖
 
python mvp_fel_toolkit.py "你的遊戲資料夾" --toggle fes_ingameoverlay.fel ARGUMENTMETER on

文字表裡還有 Argue Call、Charge Mound、 Charge Mound Available 這幾條。詳見文字表那頁。

C 組：先看再決定

C1 · 列出某個畫面現在有哪些東西是關的

python mvp_fel_toolkit.py "你的遊戲資料夾" --show fes_ingameoverlay.fel --screen INGAMEOVERLAY

輸出裡開頭有 ✕ 的那幾行就是關掉的。

C2 · 查某個元素到底顯示什麼字

python mvp_fel_toolkit.py "你的遊戲資料夾" --strings fes_hudleft.fel

這是決定要不要改之前最有用的一步 —— 名字看不出來的元素， 看它的文字通常就懂了。

C3 · 找出遊戲裡所有跟某件事有關的元素

python mvp_fel_toolkit.py "你的遊戲資料夾" --find SCORE

會掃封裝檔裡的每一個版面檔，列出檔名、行號、目前是開還是關（ingame.big 在本站測試機是 47 個，剛安裝好的原版是 44 個）。

✅ 每一則的成功標準

  • 預覽列出的行數跟本頁寫的一致（裝過模組的話可能不同，看是不是你要的元素就好）
  • 加 --apply 後印出「✅ 複驗通過」與「目標元素 0 個未套用」
  • 再跑一次 --find，那些元素的「顯示」欄變成你要的狀態

❌ 全部還原

python mvp_fel_toolkit.py "你的遊戲資料夾" --restore

不論你改了幾則、改了幾次，這一行都會回到第一次修改之前的狀態，位元組完全一致。

備份檔叫什麼名字

第一次加 --apply 的時候，工具會在 ingame.big 旁邊建一個 ingame.big.feltoolbak。

之後再改幾次都不會覆蓋它 —— 所以 --restore 永遠是回到 「你第一次動手之前」，不是「上一次修改之前」。

⚠️ 本站每支工具用的副檔名都不一樣（.bak／.speedbak／ .facebak／.feltoolbak），這樣同時用兩支工具時備份不會互相蓋掉。 診斷腳本四種都會找。

如果說找不到備份

代表你還沒 --apply 過任何東西 —— 本來就不需要還原。

📌 重點整理

  • 一句話 十則現成配方，把指令裡的路徑換掉就能用，全部靠同一支萬用工具，改錯了一行 --restore 就退回去。
  • 三組怎麼分 A 組關掉比賽畫面上的東西（打者之眼、打者姓名、球速數字、出局安打字樣、跑壘者速度），B 組把這台機器上被關掉的元素打開，C 組是決定之前先看的三個指令（--show／--strings／--find）。
  • 關鍵行數 A1 打者之眼與 A2 打者姓名是左右各 1 行、A3 球速 1 行、A4 MESSAGE 3 行、A5 跑壘者速度 6 行。行數對不上不一定是錯，因為這些是在本站測試機的檔案上量的，不是 EA 原版，裝過模組數字就可能不同，只要預覽列的是你想改的元素就可以繼續。
  • 先查文字再決定要不要改 --strings 是最有用的一步，名字看不出來的元素，看它的文字通常就懂了（PITCHSPEED1 的文字是三位數佔位字串 999，正好對得上球速）。
  • 最容易踩的雷 fes_ingamechat.fel 裡也有一個 MESSAGE，那是聊天訊息，因為指令有指定檔名所以不會改到；B 組的元素打開之後很可能什麼都不會發生，FEL 速查記載過群組的開關會被遊戲程式在執行時覆寫。
  • B 組的方向曾經講反 這一組原本叫「把 EA 自己關掉的東西打開」。拿剛安裝好的原版一比，那 36 行 EARLY／LATE／PERFECT 在原版有 24 行是開著的，本站測試機是 0 行。所以打開它是還原模組關掉的東西，不是解鎖 EA 藏起來的功能。
  • 安全網 第一次 --apply 會建 ingame.big.feltoolbak，之後再改幾次都不覆蓋，--restore 永遠回到「你第一次動手之前」而不是「上一次修改之前」，位元組完全一致。說找不到備份，代表你根本還沒 --apply 過。
  • 本站沒驗的 本站沒有實機跑過每一則的畫面結果。能保證的是檔案確實被正確修改、可以完整還原，不能保證遊戲一定會照你想的顯示；B 組更是連遊戲會不會用到那些元素都沒驗證，模組當初為什麼要關掉揮棒時機回饋，本站也不知道。
