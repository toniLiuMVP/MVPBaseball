怎麼看出哪些檔還沒被動過

你手上那份 MVP Baseball 2005，很可能早就被裝過東西了。 如果是朋友給的、或是網路上找來的整包，那幾乎是一定的。 動手改之前先搞清楚哪些檔還是原廠那一份 —— 這件事不用任何工具，看檔案的修改時間就知道。

難度

★☆☆ 只是看檔案內容以外的資訊

時間

約 2 分鐘

會改到東西嗎

不會，全程唯讀

一句話版本

遊戲資料夾裡修改時間還停在 2004 或 2005 年的檔案， 多半還是原廠那一份；時間比較新的，代表被某個東西寫過。

判準是整個 2004 年加整個 2005 年，不是某一段幾個月的區間。 出廠期的檔本來就散得很開：本站測試機那一份 data 重新掃過， 被算成出廠期的檔最早是 2004-05-04、最晚是 2005-02-09， 其中 25 個早於 2004 年 12 月。剛安裝好的原版也一樣， 它的 data 底下最早的檔是 2004-05-01。

🛟 動手之前：先完整備份整個遊戲資料夾

把整個遊戲資料夾複製一份到別的地方， 包括裡面存放紀錄的資料夾。不要挑檔案，整包複製最省事也最保險。

「紀錄」是指這些（它們跟遊戲檔混在同一個資料夾裡）：

  • Support\MVP Baseball 2005\ —— 遊戲自己建的， 裡面是設定（MVPOptions_Options.sav）與手把設定 （controller.cfg）。剛安裝好時沒有這個資料夾，玩過才出現。
  • 王朝、老闆模式、名單與玩家檔案的存檔（*_Franchise.sav、 *_Owner Mode.sav、*_Rosters.sav、*_Profile.sav）—— 沒有固定的資料夾名，你或你裝的模組包叫它什麼它就叫什麼。找不到就用這一行找：
dir /s /b "〔你的遊戲資料夾〕\*.sav"
find "〔你的遊戲資料夾〕" -name "*.sav"

上面第一行 Windows、第二行 Mac。 本站每一支工具都會自己備份它要動的那一個檔， 但那只保得住那一個檔 —— 整包備份保的是「你玩到現在的一切」。 完整做法看備份與還原 SOP。

⚡ 只想趕快做完？照這四步

  1. 下載 mvp_check_original.py。放桌面就可以，不需要放進遊戲資料夾。
  2. 開命令列跑它，把遊戲資料夾的完整路徑放在後面，路徑有空白要用引號包起來

    Windows:

    python mvp_check_original.py "你的遊戲資料夾"

    Mac / Linux:

    python3 mvp_check_original.py "你的遊戲資料夾"
    第一行會印「找到 data 資料夾,只掃它。」
    Windows 打 python3 常會跳出 Microsoft Store，那是假的：關掉， 改打 py -3 或 python（見第 0 課）。
  3. 直接看【3】各資料夾那張表：比例接近 100% 的大概沒被動過可以當比對基準，比例很低的裝過模組、要還原就從那裡找起，右邊那欄會告訴你最新被動過的那一個檔是哪一個、哪一年。
  4. 想知道球員名冊有沒有被換過，數 attrib.dat 的資料列（扣掉第一行表頭）：不是 2,921 就是被換過了。用記事本或 wc -l 直接數會得到 2,922，那是連表頭一起算的。

全程唯讀，它只讀檔案的屬性，不打開任何檔案的內容，也不連網。 結果是「先看哪裡」的地圖，不是判決。 想知道為什麼，往下讀；只想複習，跳到📌 重點整理。

為什麼值得先看一眼

本站每一課都會叫你先備份。但備份只保住「你現在這一刻的狀態」—— 如果你拿到的遊戲已經裝過三個模組，備份下來的還是那三個模組。

知道哪些檔沒被動過，有三個實際用處：

  • 出事的時候知道要還原什麼。某一課改壞了， 你至少知道原本那個檔是不是還在別的地方。
  • 看懂為什麼你的數字跟本站不一樣。 本站量到的行號、項目數、檔案大小，是本站這台機器上那一份的值。 如果你的檔案被別人改過，數字對不上是正常的。
  • 不會把別人的作品當成原廠的。 這一點對想自己做模組的人特別重要。

這個方法解掉了一個本站原本標「未解」的問題

封裝檔的檔頭到底該用哪一種位元組順序

BIGF 封裝格式那頁原本寫「檔案總大小是 little-endian」。 後來量了 295 個封裝檔，發現有 7 個是 big-endian，通則不成立。 但當時查不出為什麼，只能標「未解」。

用時間戳一交叉比對，答案立刻出來：

檔案的修改時間little-endianbig-endian
2004-2005（出廠期）1460
2012 年以後1427

出廠期的檔案沒有半個是 big-endian。 那些 big-endian 全部是後來被社群工具重新打包過的。

最乾淨的一組對照是球場檔：這台機器上同時留著兩份 dodgnite.big。 遊戲正在讀的 stadium\ 裡那一份是 2013-10-19、big-endian； 另一份 2004-12-24 的是 little-endian，擺在本站留的原廠備份 stadium - MVP2005原始\ 裡。同樣 88 個項目，只有那一欄不同。

（2026-09-05 訂正：本頁早先把這兩份的位置寫反了 —— 那時候 stadium\ 裡放的還是 2004 年那一份。上面那張表是當年量 295 個封裝檔的結果； 同一套量法今天在這台機器上重跑是 384 個（多出來的是後來擺進來的球場資料夾副本）， 出廠期 175 個 little-endian、big-endian 仍然掛零， 2012 年以後 199 個 little-endian、10 個 big-endian。結論沒有變。）

⚠ 時間戳會說謊 —— 三種情況

一、複製的方式會影響它。有些複製方式會保留原始時間， 有些會把時間變成「你複製的那一刻」。從壓縮檔解出來的通常沿用壓縮檔裡記的時間。 所以一個顯示 2023 年的檔，有可能只是被複製過，內容完全沒變。

二、時間可以被改。做模組的人如果想，可以把時間設回 2005 年。 本站沒有辦法分辨這種情況。

三、時間新不代表內容變了。有些工具只是打開檔案看一看， 卻順手把整個檔重寫了一次。

所以這是一張「先看哪裡」的地圖，不是判決。 要確定內容有沒有變，只有一個方法：拿兩份檔案逐位元組比對。

連原版裡都有一個 .bak

看到 .bak 就以為「這台被人動過」是很自然的直覺。但那個直覺會出錯。

本站把剛安裝好、從未改動的原版整份掃過， 只找到一個 .bak（那是英文版那一份；本站另一份剛安裝好的 官方繁體中文版還多一個 data\credits.BAK，2005-02-17， 同樣落在它自己的出貨期內）：

檔大小檔案日期
data\igshapes\igcrsr.fsh525,2642004-12-04 20:01:20
data\igshapes\igcrsr.fsh.bak525,184同一秒

兩個檔的時間戳一模一樣，都是 2004 年 12 月 4 日晚上 8 點 01 分 20 秒（台北時間）。 而那份英文版安裝的 data\ 底下，檔案日期全部落在 2004-05 到 2005-01 之間， 沒有任何一個檔比出貨日更晚。

⏱ 本頁的時間戳都是用台北時間讀出來的（上面那張表也是）。 同一個檔換成世界標準時間是 2004-12-04 12:01:20，兩者差 8 小時。 那批平安夜的時間戳， 以及球場速查那頁的 lighting.csv， 寫的都是世界標準時間 —— 拿它們跟這一頁對照時要先換算。「兩個檔同一秒」這件事不受影響。

（2026-09-05 訂正：這句原本寫的是「整份安裝」，那是錯的。data\ 以外 還有兩個例外：TP03Patcher.dll 是 2003-06-26，比出貨還早； filelist.txt 是 2015-05-31，比出貨晚了十年 —— 怎麼量的那一頁也記著它。）

那是 EA 自己留下的

兩份都是合法的圖片檔（同一張 512×256、同一個格式代號 0x7D）， 但內容不同：428 個位元組不一樣， 而且影像資料後面那段附加資料的長度差 80（928 對 848）。

換句話說：這是同一張游標圖的兩個版本， 開發時留下的備份跟著母片一起壓進零售版了。

本站沒有進遊戲看那兩張差在哪。未實機驗證

所以這一課的判斷要多一條

「有 .bak」不等於「被動過」。 要看的是時間戳：跟旁邊的檔同一秒、而且落在 2004–2005 之間的，是原廠的； 日期是你自己玩遊戲那幾年的，才是後來加的。

本站自己也差點在這裡誤判 —— 在「剛安裝好的原版」裡看到一個 .bak，第一反應是「那這份不乾淨」。 是看了時間戳才發現它比遊戲上市還早。

一個真實的例子：一份中文懶人包到底動了什麼

本站手上有一份 2023 年整理的中文化整合包。 把它跟剛安裝好的英文版原版比一次 —— 只比同名檔的大小，不看內容，檔名層級多出來或少掉的不算在內 —— 同名而大小不同的只有 65 個：

動了什麼幾個檔看得出來的意圖
data\fonts\fonts.big1 換成中文字型 —— 204 KB → 1.68 MB，檔名從 _en 變 _jp（為什麼是 jp）
mvp2005.exe1 主程式被改過 —— 大了 553 KB
data\frontend\61 大多是 load*.big：換載入畫面
filelist.txt1檔案清單跟著變長
Support\EasyReqs.xml1系統需求那張表：處理器從 800 MHz 寫成 700 MHz。說明文件那一整套確實換掉了（EA Help\ 274 個檔換成 European Help Files\ 276 個），但那是檔名層級的差異，不在這張表裡
data\database\（球員名冊） 0 一個位元組都沒動。
attrib.dat、team.dat、roster.dat 跟原版逐位元組相同

⚠️ 2026-09-05 訂正：上面那 65 個差異，大部分不是整合包作者動的

本站後來拿到官方繁體中文版剛安裝好的那一份，拿同一包整合包再比一次： 2,389 個同名檔，大小不同的是 0 個，繁中版有而整合包沒有的也是 0 個。 再抽驗 fonts.big、attrib.dat、frontend\load42.big、 Support\EasyReqs.xml、filelist.txt 五個檔的 SHA-256， 跟官方繁中版逐位元組相同。

換句話說：上面那張表量到的形狀，其實是 EA 官方英文版 vs EA 官方繁體中文版的差別。 中文字型、載入畫面、說明文件那幾列都是 EA 自己做的，不是整合包作者做的。 這份整合包自己加的東西是檔名層級的：比官方繁中版多出 12 個檔 （光碟映像、第三方工具、幾個執行檔變體），再加上一個大小一樣、內容不同的 mvp2005.exe —— 而「只比大小」這套方法，本來就抓不到同大小的差異。

底下那條結論不受影響，反而更硬：data\database\ 那 23 個檔在 英文版、官方繁體中文版、這份整合包三邊逐位元組相同。

這件事對你的意義

「裝了中文包」跟「球員名單被換過」是兩件不同的事。

很多人以為整合包一定連名單一起換掉了，所以不敢動。 但這一份的名冊完全是原廠的 —— 意思是你照著本站 改能力值那幾課做， 數字會跟站上寫的對得起來。

⚠️ 這是某一份整合包的結果，不是所有整合包都這樣。 你手上那份動了什麼，還是要自己看一眼 —— 最快的方法是數 attrib.dat 的資料列（扣掉第一行表頭， 用記事本或 wc -l 直接數會得到 2,922）， 不是 2,921 就是被換過了（見速查頁的拿這張表驗你自己那份名單被換過沒）。

本站不會提供那份整合包

它裡面有遊戲本體的光碟映像檔與第三方修改工具。 本站不散布、也不說明去哪裡拿。 這一節只講「拿一份已知的整合包跟原版比對，會看到什麼樣的差異形狀」。

📌 重點整理

  • 一句話 遊戲資料夾裡修改時間還停在 2004 或 2005 年的檔案多半還是原廠那一份，時間比較新的代表被某個東西寫過。判準是整個 2004 年加整個 2005 年，不是某一段幾個月的區間：本站測試機那一份 data 重新掃過，被算成出廠期的檔最早 2004-05-04、最晚 2005-02-09，其中 25 個早於 2004 年 12 月。
  • 關鍵數字（2026-09-05 重新量過）本站測試機 data\ 底下 1,090 個檔，774 個（71.0%）落在出廠期。easo\ 是 100%，本站另外留的原廠球場備份 stadium - MVP2005原始\ 88／88 也是 100%；遊戲正在讀的 stadium\ 換成 2023 年那包，只剩 34%，database\ 只有 7%，球員名冊幾乎全換，那正是台灣模組動的地方。

這支腳本在做什麼

沒讀過程式碼也沒關係，這一段把它的流程講完。

它的原理只有一句話：修改時間還停在 2004 或 2005 年的檔案， 多半還是原廠那一份。判準就是底下那張表裡的 SHIP_YEARS， 整個 2004 年加整個 2005 年，不是某一段幾個月的區間。 程式把整個 data 走一遍，只讀檔案屬性、不開任何一個檔的內容， 把每個檔按年份分成「出廠期」與「後來被寫過」兩堆， 再按第一層資料夾統計比例，最後印成四段報告。

整份只有 os.walk、os.stat、os.path.* 這些讀取呼叫， 連一個 open() 都沒有，也不連網。

哪一段做什麼為什麼要有它
SHIP_YEARS 出廠期的判準，目前是 (2004, 2005)。 這是「是不是這兩個年份之一」的比對， 不是「介於兩者之間」，所以 2006 年的檔就不算出廠期。 放寬到整整兩年，是因為不同地區、不同版本的壓片日期不一樣。 改這兩個數字等於改掉整份報告的判準。
scan() 用 os.walk 走一次資料夾， 對每個檔取最後修改時間換算成年份， 同時累加到「年份」與「第一層資料夾」兩份統計裡。 只走一次是刻意的。走兩次的話， 萬一中間有東西變了，兩段報告會互相打架，而且沒有人看得出來。 掃到讀不了的檔就跳過那一個，不讓整份掃描斷在別人的一個壞檔上； 而且會在【1】底下講明跳過了幾個、是哪幾個，那些沒有算進比例。
scan() 裡記「最新被動過的一個」那個 elif 只有「不在出廠期」的檔才會更新這個欄位， 比的是修改時間本身（st_mtime），不是只比年份。 所以那一欄記的是最新的那個被動過的檔， 不是「這個資料夾裡最新的檔」。前者才是找模組時的線索起點。 比到秒是必要的：只比年份的話，同一年裡印出來的會是 「剛好第一個被走到的那個檔」，跟先後無關。 讀程式碼時要注意那是 elif 不是 if， 兩者印出來的東西完全不同。
human() 把位元組數換成 KB、MB、GB。 誠實說：目前沒有任何地方呼叫它。 scan() 確實有把每個資料夾的總位元組數累加起來， 但【3】那張表最後沒有印出那一欄。 這件事寫在它的說明字串裡，讀原始碼的人不用自己找一遍。
main() 開頭 讀路徑；如果那底下有 data， 就自動縮到 data 只掃它。 外面那一層是安裝程式、說明檔與執行檔， 它們本來就不是判斷模組的線索，混進來只會把出廠期的比例稀釋掉。
main() 的【1】 印總檔數、出廠期檔數，以及兩者的百分比。 一個數字就看得出這一份大概是什麼狀況。 本站測試機是 1,090 個檔裡 774 個落在出廠期，71.0%。
main() 的【2】 每一年幾個檔，用 # 畫成長條圖， 檔數最多的那一年當滿格 40 格。 年份分布會直接把「這台裝過哪個年代的東西」攤開來。 長條至少畫一格，是為了讓只有一兩個檔的年份不要變成空白， 空白看起來像沒有資料，而不是「很少」。
main() 的【3】 依檔數由多到少，列出每個第一層資料夾的檔數、 出廠期檔數、比例，以及最新被動過的那一個檔。 整份輸出裡最有用的一段。 比例接近 100% 的可以當比對基準，比例很低的就是裝過模組、要還原就從那裡找起。 資料夾那一欄是照終端機的顯示寬度切的（中文字算兩格）， 所以名字裡有中文也不會把整張表推歪；最後一欄在行尾，照舊按字元數切掉尾巴。
main() 的【4】 印四行固定文字，教你怎麼讀上面三段。 很多人只會把終端機的結果複製給別人看， 那時候網頁不在旁邊。所以「時間戳是地圖不是判決」這句話， 要跟著結果一起走。

這一支沒有備份也沒有還原功能，因為它從頭到尾沒有要寫任何東西。 做不到的事一起講清楚：時間戳是檔案的屬性、不是內容的雜湊， 它證明不了內容有沒有變；要確定只有逐位元組比對一途， 那是怎麼量的那一頁的 mvp_fingerprint.py 在做的事。 它也分不出是誰改的，只知道某個檔的時間不在出廠期。 另外提醒一句：輸出第一行印的是你自己給的完整路徑， 整段貼給別人之前先把那一行遮掉（【3】那一欄的檔名是相對路徑，不帶你的帳號名）。

def human(n):
    """把位元組數換成人看得懂的單位。1 KB 一律當 1024 bytes 算。

    ⚠️ 目前這支腳本沒有任何地方呼叫它:scan() 確實把每個資料夾的總位元組數

       寫在這裡是為了讓讀原始碼的人不用自己找一遍。
    """
    # 逐級除以 1024,除到數字小於 1024 或者已經升到 GB 為止。
    for unit in ('bytes', 'KB', 'MB', 'GB'):
        if n < 1024 or unit == 'GB':
            # bytes 印整數(位元組再切小數沒有意義),其他單位印一位小數。
            return '%.1f %s' % (n, unit) if unit != 'bytes' else '%d bytes' % n
        n /= 1024.0


def pad(s, width, right=False):
    """把字串補到指定的「顯示寬度」,超出就切掉尾巴。中文字算兩格。

    不能直接用 '%-16s':那個數的是字元數,一個中文字算一格,
    但終端機上它佔兩格 —— 只要資料夾名有中文(台灣模組包很常見,
    像 `fonts - 舊版備份`),整張表就會被推歪。
    east_asian_width 回 'W'(寬)或 'F'(全形)的字算兩格,其餘算一格。
    """
    w = 0
    kept = []
    for ch in s:
        cw = 2 if unicodedata.east_asian_width(ch) in ('W', 'F') else 1
        if w + cw > width:
            break        # 切在中文字的前面,不會切出半個字
        kept.append(ch)
        w += cw
    fill = ' ' * (width - w)
    return fill + ''.join(kept) if right else ''.join(kept) + fill


def scan(root):
    """回傳 {子資料夾: {'n':檔數, 'ship':出廠期檔數, 'bytes':總大小,
                        'newest':(修改時間, 年, 相對路徑) 或 None}}

    第二個回傳值是 {年份: 檔數},給【2】那張長條圖用。
    第三個回傳值是「讀不進去而被跳過的路徑」清單(相對於 root)。
    整個函式只呼叫 os.walk 與 os.stat,一個檔案的內容都沒有打開。
    """
    out = {}
    years = {}
    skipped = []

    def note(p):
        # os.walk 預設會把讀不進去的資料夾「整個安靜地跳過」。
        # 對這支腳本特別致命:它的產出就是一個百分比,少算的檔不會留下痕跡,
        # 讀者看到的比例是錯的而他不會知道。所以全部收起來,最後印出來。
        # 存相對路徑而不是絕對路徑:這份輸出很多人會整段貼給別人看。
        try:
            rel = os.path.relpath(p, root)
        except (ValueError, TypeError):
            # ValueError:Windows 跨磁碟機時 relpath 會丟例外。
            # TypeError:例外物件沒有 filename(p 是 None)。
            rel = str(p)
        # relpath 會把 root 自己算成 '.',單獨印一個點沒有人看得懂。
        skipped.append('(你給的那個資料夾本身)' if rel == '.' else rel)

    # onerror 收的是「打不開這個資料夾」;底下 os.stat 的 except 收的是
    # 「這一個檔的屬性讀不到」。兩種都要記,不然比例會靜靜地少算。
    walk = os.walk(root, onerror=lambda e: note(getattr(e, 'filename', None)))
    for dirpath, dirnames, filenames in walk:
        # 就地改寫 dirnames 是 os.walk 的用法:改這個 list 才會讓它不要走進去,
        # 把新的 list 指派給別的名字沒有用。
        # 跳過 . 開頭是為了略過 .git 這類跟遊戲無關的東西,它們會把年份分布拉歪。
        dirnames[:] = [d for d in dirnames if not d.startswith('.')]
        for fn in filenames:
            # 檔案同理,略過 .DS_Store 這種作業系統自己產生的。
            if fn.startswith('.'):
                continue
            p = os.path.join(dirpath, fn)
            try:
                st = os.stat(p)
            except OSError:
                # 權限不足、連結斷掉、掃到一半檔案被刪掉:
                # 跳過這一個就好,不要讓整份掃描中斷在別人的一個壞檔上。
                # 但要記下來 —— 跳過幾個檔就是少算幾個檔。
                note(p)
                continue
            # st_mtime 是「最後修改時間」,用本機時區換算成年份。
            # 跨時區看同一份檔案,12/31 與 1/1 的檔可能被分到不同年;
            # 對這個用途無所謂,因為判準是「2004-2005 還是更後面」。
            y = time.localtime(st.st_mtime).tm_year
            years[y] = years.get(y, 0) + 1
            rel = os.path.relpath(dirpath, root)
            # 只取第一層資料夾名當分組。stadium\a\b\c.big 一律算進 stadium 那一列,
            # 因為玩家換模組的單位就是「哪一個資料夾」,不是「第幾層」。
            top = rel.split(os.sep)[0] if rel != '.' else '(根目錄)'
            d = out.setdefault(top, {'n': 0, 'ship': 0, 'bytes': 0, 'newest': None})
            d['n'] += 1
            d['bytes'] += st.st_size
            if y in SHIP_YEARS:
                d['ship'] += 1
            elif d['newest'] is None or st.st_mtime > d['newest'][0]:
                # 注意這是 elif:出廠期的檔永遠不會更新 newest。
                # 所以 newest 記的是「最新的那個被動過的檔」,
                # 不是「這個資料夾裡最新的檔」。前者才是讀者要找的線索起點。
                # 比的是 st_mtime 不是年份:同一年裡也要挑真正最後被寫過的那一個,
                # 只比年份的話會變成「那一年裡剛好第一個被走到的檔」,跟先後無關。
                d['newest'] = (st.st_mtime, y, os.path.relpath(p, root))
    return out, years, skipped


def main():
    """讀參數、掃一次資料夾,然後把四段報告印出來。"""
    # 這裡濾的是單一個 '-' 開頭(姊妹腳本 mvp_check_setup.py 濾的是 '--'),
    # 所以 -h 與 --help 都不會被誤當成路徑。
    args = [a for a in sys.argv[1:] if not a.startswith('-')]
    if '--help' in sys.argv or '-h' in sys.argv or not args:
        # 沒給路徑,跟明講要看說明,都印檔頭那份文件。
        # 這裡回 0 不是 1:使用者問用法而他得到了用法,那不是錯誤。
        print(__doc__)
        return 0

    root = args[0]
    # 給的是安裝資料夾的話就自動縮到 data:遊戲的內容都在那裡,
    # 外面那層是安裝程式與說明檔,混進來只會把出廠期的比例稀釋掉。
    data = os.path.join(root, 'data')
    if os.path.isdir(data):
        root = data
        print('  找到 data 資料夾,只掃它。')
    elif not os.path.isdir(root):
        print('  找不到這個資料夾:%s' % root)
        print('  請把遊戲安裝資料夾的完整路徑放在後面,例如:')
        print('    python3 mvp_check_original.py "C:\\Program Files (x86)\\EA SPORTS\\MVP Baseball 2005"')
        return 1

    print('  掃描 %s' % root)
    print()
    # 只走一次資料夾,四段報告全部從這一次的結果算出來。
    # 走兩次的話,萬一中間有東西變了,兩段報告會互相打架而且沒人看得出來。
    out, years, skipped = scan(root)
    total = sum(d['n'] for d in out.values())
    ship = sum(d['ship'] for d in out.values())
    if not total:
        if skipped:
            # 一個檔都沒讀到、而且掃描過程有東西讀不進去 —— 那是權限問題,
            # 不是路徑問題。講成「路徑可能給錯了」會害讀者去改一個沒有錯的路徑。
            print('  這裡一個檔都讀不到,但不是空的:有 %d 個路徑因為權限不足'
                  % len(skipped))
            print('  或掃描當下被鎖住而跳過:')
            for rel in sorted(skipped)[:5]:
                print('       · %s' % rel)
            if len(skipped) > 5:
                print('       · …還有 %d 個沒列出來。' % (len(skipped) - 5))
            print('  先確認你對它有讀取權限,路徑不必改')
            print('  (Windows 可以改用「以系統管理員身分執行」再跑一次)。')
        else:
            print('  這個資料夾裡沒有檔案。路徑可能給錯了。')
        return 1

    print('  【1】整體')
    print('    共 %d 個檔,其中 %d 個的時間落在 %d-%d 年(%.1f%%)。'
          % (total, ship, SHIP_YEARS[0], SHIP_YEARS[1], ship * 100.0 / total))
    if skipped:
        # 少算的檔一定要講出來,不然上面那個百分比是錯的而沒有人看得出來。
        print('    ⚠️ 另有 %d 個路徑讀不進去(權限不足或掃描當下被鎖住),'
              % len(skipped))
        print('       沒有算進上面這個比例:')
        for rel in sorted(skipped)[:5]:   # 排序過,同一台機器重跑列出來的是同幾個
            print('       · %s' % rel)
        if len(skipped) > 5:
            print('       · …還有 %d 個沒列出來。' % (len(skipped) - 5))
    print()

    print('  【2】各年份有幾個檔')
    # 長條圖以「檔數最多的那一年」當滿格 40 個 #,其他年份照比例縮。
    top = max(years.values())
    for y in sorted(years):
        mark = ' ← 出廠期' if y in SHIP_YEARS else ''
        # max(1, ...) 保證只有一兩個檔的年份也看得到一格。
        # 少了這個保護,那些年會變成空白,看起來像沒有資料而不是「很少」。
        bar = '#' * max(1, int(round(years[y] * 40.0 / top)))
        print('    %d  %5d  %s%s' % (y, years[y], bar, mark))
    print()

    print('  【3】各資料夾')
    # 整份輸出裡最有用的一段。依檔數由多到少排,量體大的資料夾先看到。
    print('    %s %s %s %s   %s'
          % (pad('資料夾', 16), pad('檔數', 6, True), pad('出廠期', 8, True),
             pad('比例', 7, True), '最新被動過的一個'))
    for k, d in sorted(out.items(), key=lambda x: -x[1]['n']):
        pct = d['ship'] * 100.0 / d['n']
        # newest 只有在出現過「非出廠期」的檔時才有值(否則是 None),
        # 所以沒值就代表這個資料夾整個沒被動過。
        newest = '%d 年 %s' % (d['newest'][1], d['newest'][2]) if d['newest'] else '(全是出廠期)'
        # 資料夾欄用 pad() 依「顯示寬度」切到 16 格 —— 中文字佔兩格,
        # 用 %-16s 只要名字有中文就會歪掉。最後一欄在行尾,不影響對齊,
        # 所以照舊用字元數硬切 44。切掉的都是尾巴,前面那段通常就夠認人。
        print('    %s %6d %8d %6.0f%%   %s' % (pad(k, 16), d['n'], d['ship'], pct, newest[:44]))
    print()

    # 最後這一段是固定文字,不是算出來的。放進輸出而不是只寫在網頁上,
    # 是因為很多人只會把終端機的結果複製給別人看,那時候網頁不在旁邊。
    print('  【4】怎麼讀這份結果')
    print('    比例接近 100% 的資料夾:大概沒被動過,可以當成比對的基準。')
    print('    比例很低的資料夾:裝過模組。要還原就從這裡找。')
    print('    ⚠️ 時間戳會說謊 —— 有些複製方式不保留時間,也有人會刻意改。')
    print('       這是「先看哪裡」的地圖,不是判決。')
    return 0


if __name__ == '__main__':
    sys.exit(main())
