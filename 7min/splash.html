七分鐘 › 開始畫面

七分鐘學會置換遊戲開始畫面並匯入遊戲

遊戲開頭那三張圖，本站量出它們在哪、多大、什麼格式，並寫了一支腳本做這件事。 三張都匯得出來，但目前只有標題頁（title）與讀取畫面（loading）匯得回去； 開機大圖（splash）會被擋，原因寫在下面「這一課到哪裡為止」。

⏱ 七分鐘怎麼分配

做什麼分鐘
看三個畫面各是什麼規格1
匯出一張當範本1
改圖3
匯入1
開遊戲確認1

前置

  • 已安裝的 MVP Baseball 2005
  • Python 3
  • 任何能存 PNG 的繪圖軟體
  • 下載 mvp_swap_screen.py。下載的檔會在「下載」資料夾：打開檔案總管左邊的「下載」，點一下最上面的網址列，把字刪掉改打 cmd 按 Enter，後面的指令都在開出來的這個視窗打（Mac 開終端機先打 cd ~/Downloads）

🛟 動手之前：先完整備份整個遊戲資料夾

把整個遊戲資料夾複製一份到別的地方， 包括裡面存放紀錄的資料夾。

怎麼整包複製、紀錄（王朝、名單、設定）放在哪、找不到怎麼找： 看備份與還原 SOP 的「整包複製」。

👉 你要做的事

1

先看有哪三個畫面可以換。

Windows:

python mvp_swap_screen.py "〔你的遊戲資料夾〕" --info

Mac / Linux:

python3 mvp_swap_screen.py "〔你的遊戲資料夾〕" --info
代號是什麼尺寸格式
splash開機大圖1024 × 1024
（原版 512 × 512）		DXT1
title標題頁 / 授權畫面1024 × 51232 位元
loading讀取中那張512 × 51232 位元
2

匯出現在那張當範本。

Windows:

python mvp_swap_screen.py "〔你的遊戲資料夾〕" --export title old.png

Mac / Linux:

python3 mvp_swap_screen.py "〔你的遊戲資料夾〕" --export title old.png

代號換成 loading 也可以。splash 也匯得出來， 但它匯不回去，所以這一課不拿它當例子。

old.png 會存在命令視窗所在的資料夾（照前置那樣從「下載」開的話，就在「下載」裡）；改好存成 mine.png，也放在同一個資料夾。

3

用繪圖軟體改，存成 PNG。

⚠ 尺寸必須完全一樣

不一樣就直接拒絕寫入，腳本不會幫你縮放。最穩的做法是在匯出的那張上面直接改。

4

匯入。先預覽，再加 --apply。

Windows:

python mvp_swap_screen.py "〔你的遊戲資料夾〕" --import title mine.png

Mac / Linux:

python3 mvp_swap_screen.py "〔你的遊戲資料夾〕" --import title mine.png

確認沒問題之後，同一行後面加 --apply。

✅ 怎麼知道成功了

  • --info 印出三個畫面的規格
  • 匯出的 PNG 打得開，就是你現在遊戲裡看到的那張
  • 匯入預覽沒有報長度錯誤（換 splash 一定會報，那不是你的問題）
  • 開遊戲看那張畫面

❌ 出錯處理

症狀怎麼辦
can't open file '…mvp_*.py' 命令視窗跟腳本不在同一個資料夾。 打開放著那個 .py 的資料夾（剛下載的話就是「下載」），在網址列打 cmd 按 Enter，用新開的視窗再跑一次（Mac 用 cd 切過去，例如 cd ~/Downloads）。 還是一樣的話，是檔名對不上：瀏覽器可能在檔名後面加了 (1)，把它改成跟指令裡一模一樣
說尺寸不對用匯出來的那張當底圖。換 splash 的話換底圖也沒用，它現在匯不回去
圖變模糊title 與 loading 是 32 位元未壓縮，不會糊；會糊的是 DXT1 的 splash，而它目前匯不回去
想還原--restore

⚠️ 這一課到哪裡為止

開機大圖（splash）目前匯不回去。 三張都匯得出來，但 splash 連 --export 出來的那張原封不動匯回去也會被擋。 本站手上六份 data 資料夾都一樣：splash 是 1024 × 1024 的兩份說 新像素有 524288 個位元組,原本是 524304，512 × 512 的四份說 新像素有 131072 個位元組,原本是 131088。差的永遠是 16 個位元組， 完整說明在換掉開機畫面。

splash 是 DXT1 有損壓縮，就算哪天匯得回去也會掉一點畫質， 本站沒有無損的路；title 與 loading 是 32 位元未壓縮，沒有這個問題。

腳本只處理 0x60（DXT1）與 0x7D（32 位元）兩種格式， 遊戲裡其他格式的圖它會直接拒絕，不會亂猜。

換完之後遊戲畫面實際長什麼樣，本站沒看到。 驗的是「檔案寫進去了、而且寫的內容正確」，不是「遊戲顯示正常」。

🔍 這一課怎麼查出來的（順便示範一次證據強度）

2007 年有一份社群工具的說明寫「開機畫面是遊戲根目錄的 00000000.256」。本站測的這台機器上，整個遊戲一個 .256 都沒有，執行檔裡也搜不到那個字串。

真正的線索在兩個地方對上：執行檔的符號表裡有 FSPLASH、LEGAL、LOADING;而版面檔 fes_title.fel 寫著 SH:CLICKME,…,lice,lice ——而 license.fsh 裡那張圖的名字就叫 lice。

這是名字對上名字，不是數量對上數量。本站把後者列為最弱的一級證據。

⚠️ 但本站不能斷定那份 2007 年的說明當年是錯的——也可能是某個版本或某個安裝方式才有。本站只能說：在這台機器上它不存在，而 splash.fsh 存在。

  • 圖片的像素怎麼排
