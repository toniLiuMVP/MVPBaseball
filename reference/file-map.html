遊戲檔案地圖

想改遊戲裡的東西，第一個問題永遠是「它在哪個檔案」。 這頁把 data\ 底下的 224 個封裝檔依用途分類， 從你想改的東西反查到檔案。

⚠️ 說清楚一下這個 224：那是 data\ 底下副檔名叫 .big 的檔案數。其中真正是 BIGF 封裝格式的只有 207 個 —— 另外 8 個開頭是 SCHl(音訊容器)、1 個是 SHPI(圖片)、8 個沒有可辨識的開頭。站上其他地方講「224 個封裝檔」是沿用習慣講法，需要精確數字的時候以這裡為準。
另外要說的是：本頁的檔案大小與項目數量自本站測試機那台裝過模組的遊戲。224 這個檔數剛安裝好的原版也一樣（本站測試機是扣掉個人備份檔之後的數字），但容量差很多 —— 原版的 portrait.big 是 104.2 MB、models.big 是 165.0 MB，對照見原版與這台機器差在哪。

⚠️ 本站改過這張樹狀圖

上線時這張圖少了三個資料夾：datafile\、 easo\、igshapes\。

原因是這張表數的是「封裝檔」，不是「檔案」。 完全沒有封裝檔的資料夾，在製表的時候就整個消失了。 不過這只解釋得了 easo\ 與 igshapes\：datafile\ 自己就有一個封裝檔（datafile.big），那一個是單純漏抄 —— 而 easo\ 裡面有 519 個檔，是全遊戲檔案數最多的資料夾， 第二名的 frontend\ 只有一百出頭。

那 519 個檔是一整套 2005 年的社群網站， 現在站上有一整篇在講它。

教訓：用某個條件產生的清單，會把不符合那個條件的東西變成看不見。 表格上寫「N 個」的時候，要說清楚數的是什麼。

遊戲資料夾在哪

上面那張樹狀圖的 data\ 就在遊戲安裝資料夾底下。舉例來說，比賽中介面那個檔的完整路徑長這樣：

<遊戲安裝資料夾>\data\frontend\ingame.big

路徑結尾的 data\frontend\ 就是上面樹狀圖裡的 frontend\， 把 frontend\ 去掉就是 data\ 本身。 遊戲安裝資料夾常見的位置有下面這幾種：

系統路徑
WindowsC:\Program Files (x86)\EA SPORTS\MVP Baseball 2005\data\frontend\
WindowsC:\Program Files (x86)\EA Games\MVP Baseball 2005\data\frontend\
綠色版 / 免安裝<你自己解壓的資料夾>\data\frontend\
Mac（Wine / CrossOver）~/…/drive_c/Program Files (x86)/EA SPORTS/MVP Baseball 2005/data/frontend/

裝在別的磁碟或自訂資料夾也很常見，上表只是最常遇到的幾種。 真正的判準是：那個資料夾底下要有一個 data\。

這幾個檔名長得很像，別拿錯

frontend\ 底下有一批名字很接近的 .big。 本站比賽中介面的教學要改的是 ingame.big —— 不是 igonly.big、不是 frontend.big、也不是 feonly.big。這四個都是真實存在的檔案， 所以挑錯一個不會跳出「找不到檔案」，只會改到別的地方去。

我們改過這張表

這頁上線時，表上寫「cd 是選單音樂，佔音訊 99%， 而遊戲中的播報、觀眾、應援加起來不到 1%」，還附了一段「音樂用串流、音效要常駐記憶體」的解釋。

重新量測後發現寫反了。選單音樂只有 84.2 MB， 佔音訊總量 11.4%；語音與音效是 644.8 MB，佔 87.5%。 光是主播語音一區就有 330.2 MB。那段記憶體的解釋是推測，沒有依據，已一併移除。

寫錯了就改，並且說明改了什麼。

目前還改不了的東西

誠實說明：不是所有東西都已經解開。以下是目前已知的邊界。

第一列本站在 2026-08-28 自己推翻了。 它留在表上是因為那次判斷錯在哪比結論本身更值得記住 —— 詳見那一列。

想改的卡在哪
播報語音內容
（2026-08-28 訂正：這一格改得動）		 換掉主播唸的名字做得到，社群二十年前就做了 —— 本站原本把它列在這裡是把「未解」貼錯了層次： 要換語音需要的是「產生一個遊戲吃得下去的檔」，不是「把 EA 錄的解碼出來」。 詳見播報與音訊系統的訂正與換掉遊戲的聲音。 還沒釐清的是音檔索引跨三個檔案的編號系統彼此對不上。 （2026-08-29 訂正：這裡原本還列著「15 個位元組怎麼還原成 28 個取樣」，那一格已經解開，對照 ffmpeg 驗過 21,678,328 個取樣 0 個不同 ——見換掉遊戲的聲音。）
字型字模容器層已解開，但每個字的點陣圖與間距資料還沒
動畫動作本身動畫資料是編譯過的 3D 骨架關鍵影格，改它接近重寫一套 3D 軟體
球場 3D 結構可以換貼圖、改光源，但重建球場幾何需要完整的 3D 管線

務實的結論：檔案層級的替換（換圖、換音檔、換數值）已經能滿足絕大多數需求。 真正需要重建 3D 結構的情況很少。

📌 重點整理

  • 一句話 想改遊戲裡的任何東西，第一個問題永遠是「它在哪個檔案」，這一頁把 data\ 底下的封裝檔依用途分類，讓你從想改的東西反查到檔案。
  • 那個 224 要看清楚 224 是副檔名叫 .big 的檔案數，真正是 BIGF 封裝格式的只有 207 個（8 個開頭是 SCHl、1 個是 SHPI、8 個沒有可辨識的開頭）。站上其他地方講「224 個封裝檔」是沿用習慣講法，需要精確數字時以這一頁為準。
  • 容量集中在少數幾個檔 frontend\ 98 個裡，6 個視覺資源就佔了這個資料夾八成容量，光 portrait.big 一個檔 253.6 MB；根目錄的 models.big 535.9 MB，是表上風險標最高的一個（容量量自本站測試機，剛安裝好的原版分別是 104.2 MB 與 165.0 MB）。stadium\ 87 個、audio\ 28 個。
  • 本站訂正一：樹狀圖少了三個資料夾 上線時漏了 datafile\、easo\、igshapes\。原因是那張表數的是「封裝檔」不是「檔案」，完全沒有封裝檔的資料夾在製表時整個消失 —— 這解釋得了 easo\ 與 igshapes\，但解釋不了 datafile\：它自己就有一個封裝檔（datafile.big），那一個是單純漏抄。而 easo\ 裡有 519 個檔，是全遊戲檔案數最多的資料夾。教訓：用某個條件產生的清單，會把不符合那個條件的東西變成看不見。
  • 本站訂正二：音訊那張表寫反了 原本寫「cd 是選單音樂，佔音訊 99%，遊戲中的播報與觀眾加起來不到 1%」。重新量測後是相反的：選單音樂只有 84.2 MB（11.4%），語音與音效 644.8 MB（87.5%），光主播語音一區就 330.2 MB。當時附的「音樂用串流、音效要常駐記憶體」是沒有依據的推測，已一併移除。
  • 索引跟聲音是分開放的 audio\ 底下大部分資料夾看起來都很小，因為它們只放索引，真正的聲音全部在 cd\ 底下（佔音訊 98.9%）。想知道某一區實際多大，要看 cd\ 裡的同名資料夾。
  • 最容易拿錯的檔 frontend\ 底下有 ingame.big、igonly.big、frontend.big、feonly.big 四個名字很像的真實存在的檔案。挑錯一個不會跳出「找不到檔案」，只會改到別的地方去。
  • 本站沒驗的 字型的容器層解開了，每個字的點陣圖與間距沒有；動畫是編譯過的 3D 骨架關鍵影格；球場可以換貼圖改光源，但重建幾何需要完整的 3D 管線。這三格目前都改不動。播報語音原本也列在這裡，2026-08-28 訂正為做得到（見音訊那頁的訂正）；那裡剩下的未解是音檔索引跨三個檔案的編號系統彼此對不上，不是「換不了」；「15 個位元組怎麼還原成 28 個取樣」那一格已經在 2026-08-29 解開（見上面「目前還改不了的東西」那一列的訂正與換掉遊戲的聲音）。
